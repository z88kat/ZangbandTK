# File: town.txt
#
# The names the world's towns are drawn from (WLD-11).
#
# Zangband named its towns: select_town_name() in wild2.c took a generated
# "elvish" name from Angband's syllable tables and hung a suffix on it by size
# -- "-ville" for a hamlet, " Dun", "-ton", "-ford".  That is a name generator
# for Middle-earth, and DEC-30 points this game the other way, so the names are
# curated here rather than generated.
#
# === On the sourcing of these names, honestly ===
#
# The agreed reference for the setting is the Wikipedia article on the
# Chronicles of Amber (DEC-30).  Read for place names, it yields very few:
# Amber, Castle Amber, Tir-na Nog'th, the Forest of Arden, Avalon, and the
# Courts of Chaos.  Four of those are already dungeon names in dungeon.txt, so
# the article alone cannot name a world's towns.
#
# The lists below are therefore in two tiers, and the second wants checking
# against the novels by somebody holding them:
#
#   confirmed  - present in the agreed reference.
#   novels     - believed to be Zelazny's, from the Chronicles, but not in the
#                article and not verified against the books.  If one of these is
#                wrong, it is wrong here and nowhere else: delete the line.
#
# Nothing below is invented.  If a name is wanted that is not Zelazny's, add it
# and say so in a comment, so the distinction survives.
#
# === Understanding town.txt ===
#
# name:settled:<name>   a place in country that is governed.  Villages, towns,
#                       cities and great cities with people in them draw here.
# name:lawless:<name>   a place that has fallen, or was never governed.  Towns
#                       held by monsters, and towns standing empty, draw here.
#
# Order matters only in that a world assigns names in the order it places its
# towns, so reordering the file renames the towns of every existing character's
# world.  Adding to the end does not.

#---------------------------------------------------------------------
# Constants for non-O critical calculations
# In general, those calculations compute the chance for a critical
# from a linear combination of the to-hit bonuses, the player's
# to-hit skill, the player's level, and the weapon or missile's
# weight.  If a critical happens, they then compute the power (i.e.
# severity of the critical) from a random term and the weapon or
# missile's weight.  For more details see critical_melee() and
# critical_shot() in player-attack.c.
#---------------------------------------------------------------------

# Amount added to the to-hit value for calculating the chance of a melee
# critical when the target is debuffed
melee-critical:debuff-toh:10

# Scale factor for the weapon's weight in the chance for a melee critical
melee-critical:chance-weight-scale:1

# Scale factor for the overall to-hit value when calculating the chance
# for a melee critical
melee-critical:chance-toh-scale:5

# Scale factor for player level when calculating the chance for a melee critical
melee-critical:chance-level-scale:0

# Scale factor for the to-hit skill when calculating the chance for a melee
# critical
melee-critical:chance-toh-skill-scale:1

# Value added to the chance for a melee critical
melee-critical:chance-offset:-60

# Maximum range for melee critical chance; if the chance is N and the maximum
# range is M, then the probability a critical will happen is
# min(max(0, N), M) / M; to avoid extra inaccuracies for the damage shown
# within object descriptions, this should be a multiple of 100
melee-critical:chance-range:5000

# Scale factor for the weapon weight in the power of a melee critical
melee-critical:power-weight-scale:1

# The maximum of the random part of the power for a melee critical
melee-critical:power-random:650

# Define each of the levels for melee criticals.  If no critical levels are
# defined, then there's no extra damage due to critical hits.
# The first value is the cutoff for the power.  Any critical which has a power
# less than that cutoff and is not covered by a lower power level will fall
# in that level.  The cutoff for the last level is not used and that level
# will catch any criticals not caught by the previous levels.  To be valid,
# the cutoffs for all levels but the last must be in scrictly ascending order.
# The second value is the damage multiplier for that power level.
# The third value is the amount added to the damage for that power level.
# The fourth value is the name of the message, from list-messages.h, to use when
# a critical happens for that power level.
melee-critical-level:400:2:5:HIT_GOOD
melee-critical-level:700:2:10:HIT_GREAT
melee-critical-level:900:3:15:HIT_SUPERB
melee-critical-level:1300:3:20:HIT_HI_GREAT
melee-critical-level:-1:4:20:HIT_HI_SUPERB

#---------------------------------------------------------------------
# Constants for O critical calculations
# In general, those calculations compute a "power" of the critical
# by scaling the chance of a hit.  The "power" is then converted to
# a chance of a critical using (a * power) / (b * power + c) as the
# chance where a, b, and c are constants specified here.  For more
# details, see o_critical_melee() and o_critical_shot() in
# player-attack.c.
#---------------------------------------------------------------------

# Amount added to the to-hit value for calculating the power of a melee critical
# when the target is debuffed

# The numerator for the scale factor applied to the combined to-hit value to
# get the power of the critical

# The denominator for the scale factor applied to the combined to-hit value to
# get the power of the critical
o-melee-critical:power-toh-scale-denominator:3

# The scale factor for the critical's power in the numerator for the chance
# of the critical
o-melee-critical:chance-power-scale-numerator:1

# The scale factor for the critical's power in the denominator for the chance
# of the critical
o-melee-critical:chance-power-scale-denominator:1

# Value of an added term in the denominator for the chance of a critical
o-melee-critical:chance-add-denominator:240

# Define each of the levels for melee criticals.  They are considered in the
# order they appear so it's convenient to put the least likely first.  If no
# critical levels are defined, then there's no extra damage due to critical
# hits.
# Except for the last level, one over the first value is the probability that
# this level occurs when none of the prior levels have been selected; the last
# level will always be used if none of the prior levels have been selected.
# The first value must be positive.
# The second value is the number of dice to add for the critical.  It must be
# non-negative.
# The third value is the name of the message, from list-messages.h, to use
# when a critical happens for that power level.

o-melee-critical-level:3:3:HIT_SUPERB
o-melee-critical-level:2:2:HIT_GREAT

# === ZangbandTK lethality scalars ===
#
# The project's primary balance dial. Applied to every monster's base values at
# load time, as a percentage.
#
# Zangband's monsters carry roughly three quarters of Angband's hit points and
# half its armour class -- measured at 0.73x and 0.50x across the 450 monsters
# Angband 2.8.1 and Zangband 2.7.5 share. Rather than importing Zangband's
# per-monster numbers, which would discard twenty-five years of relative tuning,
# we scale Angband 4.2's own values by those deltas. That preserves 4.2's
# balance *between* monsters while adopting Zangband's absolute lethality.
#
# Note that this is the *only* mechanism by which ZangbandTK moves faster than
# vanilla. Zangband's experience system turned out to be identical to Angband's
# once the differing award formulae are accounted for, so pace comes from
# monsters dying sooner rather than from inflated rewards.
#
# Set both to 100 to play at vanilla Angband lethality.

# Percentage of base hit points every monster receives
lethality:hit-points:73

# Percentage of base armour class every monster receives
lethality:armor-class:50

# === ZangbandTK melee weapon mechanics ===
#
# Frequencies for the three Zangband weapon properties Angband has no
# counterpart for. Only playtest can settle these, so they live in data.

# How long a blessed beast's gift lingers, in turns.  For that long no other
# beast will give you another, which is what stops a full heal for nothing from
# being a full heal whenever you like: white deer are common, and the memory
# cannot live on the animal.
world:blessing-turns:500

# How far a blessed beast bounds after it has been touched, in grids.  Far
# enough to be outside its own hearing, or it simply turns round and comes
# back: a white deer moves at speed 130 and hears at 40, so a short bound only
# means it is beside you again a few paces later, shying away from a hand it
# has already refused.  Reported from play twice.
world:blessing-bound:100

# A vorpal weapon cuts deep on one blow in this many
melee:vorpal-chance:6

# ...and multiplies that blow's damage by this
melee:vorpal-multiplier:2

# A chaotic weapon discharges an effect on one blow in this many
melee:chaotic-chance:7

# === ZangbandTK wilderness ===
#
# The overworld is a grid of blocks, each generated on demand from the world
# seed and its own coordinates, and cached while the player is near it.
#
# 'blocks' must be a power of two plus one: the plasma fractal that lays out
# the world's height, population and law maps subdivides by halves and needs
# both edges to land on a sample point.
#
# Zangband's own 129 (2^7 + 1), a world of 2064x2064 grids. DEC-19 started this
# at a quarter of that linear dimension on the grounds that the wilderness was
# the project's largest memory risk -- but the measurement in the world
# requirements, section 6, put the risk in block *contents*, and contents are
# generated on demand and never stored. The map itself is six bytes a block:
# 129x129 is 100KB, and generating it is three plasma fractals that do not
# register on a clock. There was nothing to be bought by being small, and a
# 528x528 world put the map edge a few minutes' walk from the town.

# Width and height of the world, in blocks. Must be 2^n + 1.
wild:blocks:129

# Width and height of one wilderness block, in grids
wild:block-size:16

# Blocks held in memory at once. Zangband kept 9x9 live around the player.
wild:cache-blocks:81

# Wilderness monsters (CNT-05).
#
# Odds against any one grid of the live surface holding a monster, before the
# land's own fertility is taken into account: the actual odds are this divided
# by one plus the block's density, so barren country is close to empty and
# living country is not. Monsters are bolder after dark.
#
# Zangband's figures were 32786 and 20000, and these are half of them -- twice
# the density -- for a reason about our implementation rather than about taste.
# Our surface is one window that persists for a long walk and re-rolls only when
# it scrolls, where Zangband rolled monsters into each block as the block came
# into existence and a walking player made new blocks constantly. Same odds per
# grid, much deader country.
#
# Measured, so the number is understood rather than guessed: about 15 monsters
# over the 20,736 grids of the live window -- one per 1,400 grids, against a
# sight radius covering about 1,250. So roughly one in view at a time, half of
# them asleep. That is sparse on purpose. Open country should be emptier than a
# dungeon, and a wilderness you cross without meeting anything is a wilderness.
#
# Lower these if it wants to be busier; 6000/4000 puts about three in view.
wild:monster-rarity-day:16000
wild:monster-rarity-night:10000

# How long something you drop stays where you dropped it (WLD-04a), in days,
# before the odds are even that somebody has walked off with it.
#
# This is the figure for the emptiest country there is. It falls with how many
# people the land supports, so a sword left outside a city gate is gone by
# morning and one dropped in a waste may lie there a good while. A half-life
# rather than a deadline: most things go early and the occasional one survives
# a remarkably long time, which is how lost property behaves.
wild:relic-half-life:3

# How many quests a character may have running at once (WLD-16d).
#
# Room in the quest list beyond the fixed ones from quest.txt, which are the
# quests the game is *won* by and are not taken from anybody. A quest taken from
# a building goes in one of these, and is freed again when it is handed back.
wild:quest-slots:8

# Rivers and lakes (WLD-08), Zangband's own figures.
#
# Rivers start from this many points squared, spread evenly over the map: 4
# gives 16 sources, each linked to its nearest neighbour and run downhill to the
# sea. Lakes are attempts rather than results -- one that lands on the coast is
# abandoned rather than moved, which is why there are usually fewer than asked.
wild:rivers:4
wild:lakes:4

# How near two towns must be, in blocks, to get a road directly between them
# (WLD-08). Zangband's ROAD_DIST is 30 and that is kept as the reference. Every
# town is already reachable: the roads are laid as a spanning tree over the
# towns first, so there is always a road out of the village that leads to all
# the rest. This value only decides how much of a *network* the settled parts
# of the world get on top of that.
wild:road-dist:30

# What the magetower charges to carry you, in gold per block travelled
# (WLD-16c). Distance is measured across the block map, so a hop to the next
# valley is cheap and crossing the world is not. At 15 a twenty-block trip is
# 300 gold, which is real money to a character of level five and nothing to one
# of level thirty -- which is the right shape: the network is a convenience you
# grow into, not a way past the early game.
wild:travel-cost:15

# What the town services charge (WLD-16c). All in gold.
#
# heal-cost is per hit point restored, so mending a scratch is pennies and
# mending a near-death is not. The rest are flat: curing every ailment at once,
# restoring every drained stat at once, restoring lost experience, a bed at the
# inn until morning, one enchantment from the magesmith, one recharge.
#
# Pitched so that a character of level five feels them and one of level thirty
# does not, which is the same shape as the magetower's fare: a service is a use
# for gold, and gold stops being scarce.
wild:heal-cost:4
wild:ailment-cost:60
wild:restore-cost:400
wild:inn-cost:25
wild:enchant-cost:250
wild:recharge-cost:120

# How long a town gate stands open before it swings shut, in game turns. A
# player at normal speed acts every ten of these, so 100 is about ten moves --
# long enough to walk through and lead a packhorse, short enough that the gate
# is shut again by the time anything follows you home.
wild:gate-turns:100

# How many towns to place (WLD-10). Zangband's reference is 20; twelve on a
# 129-block world leaves them a good walk apart without the map feeling empty.
# The first is always the starting village, and is always the smallest band.
wild:towns:12

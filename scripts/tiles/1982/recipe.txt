# recipe.txt -- how every 1982 tile is cut from the generator's sheets.
#
# A copy of accepted.txt from the design brief (.claude/plans/
# design_brief_tileset_1982/), where the sheets it names live; they are 93 MB
# of JPEG and PNG and are not in the repository.  build-1982.py --cut reads
# this and those sheets once and writes source.png, which is what the build
# reads from then on.  Change the brief's accepted.txt, copy it here, and cut
# again.
#

# accepted.txt -- every tile of the 1982 set that has been accepted, and where
# its art is.  The importer reads this; nothing else says which take won.
#
#   <id> <sheet> <cell> [<from>><to> ...]
#
# The sheets are 1024x1024 or 2048x2048, a 4x4 grid of square cells numbered
# 1 to 16 left to right, then top to bottom.  A tile is cut by averaging each
# block of a thirty-second of its cell (8x8 or 16x16) into one pixel and
# snapping it to DB16 (palette.hex).
# Recolourable tiles (sprites.csv says which) snap to DB16 without plum,
# iron, stone, steel and bone, plus the four recolour greys.  Outside
# terrain, a block that is mostly magenta is transparent.
#
# The swaps after the cell are colour changes made after snapping, all at
# once (plum>brown brown>orange turns plum brown and brown orange; nothing
# becomes orange twice).  The names are palette.png's; a recolour grey is
# named by its hex (333333, 666666, 999999, cccccc).
#
# A step written clear:<x0>-<x1>,<y0>-<y1> makes that rectangle of the cut
# tile transparent, counting from 0 at the top left, before any outline.
# It removes a neighbour's art that spilled over the cell's edge.
#
# A step written at:<x>,<y>,<size> cuts the tile from that square of the
# sheet instead of from the cell, in sheet pixels from the top left, each
# art pixel a block of size/32; anything beyond the sheet's edge counts as
# magenta.  The step largest keeps only the largest shape in the tile
# (pixels touching on a side or a corner), dropping whatever else the
# square caught.  The step own keeps only the shapes whose middle falls
# inside the line's cell, the shapes being found on the whole sheet at a
# quarter of its size (a pixel is part of one when at least two of its
# four samples aren't magenta; shapes join on a side or a corner); every
# other pixel in the square counts as magenta.  Batch 16's and batch 21's
# figures needed these: they were drawn a fifth of a cell above their rows,
# some taller than a cell.
#
# The step thin:<f> keeps a block when at least f of its pixels aren't
# magenta, instead of more than half, for art drawn as faint lines that
# would otherwise average away into the background (batch 30's It).
#
# clear and largest apply first, in the order written, then the colour
# swaps together, then the outline.
#
# A swap to none (red>none) makes that colour transparent, for a glow
# drawn round something that should stand clear of the floor.
#
# A swap written +<rrggbb>><to> works before snapping instead: it adds the
# colour rrggbb to the palette for that tile alone, and every block that
# snaps to it becomes <to>.  It catches a colour the generator used that is
# nearer the wrong palette entry (the high mages' crimson, #901830, is nearer
# brown than DB16's red).
#
# The id is sprites.csv's for the first set.  An individual tile (one
# monster's own, after the first set) uses monsters.csv's id, except
# mon-corwin, which is mon-corwin-lord-of-avalon; a shared drawing uses
# second-set.csv's.  Which tile each monster shows is monsters.csv's own_tile.  A # starts a comment, whether at the start of a
# line or after a tile.  A later line for the same id replaces an earlier one.
#
# The heroine tiles (player-<class>-f) need the game to say which the
# player is, and it doesn't: 4.2 has no sex.  The Tk portraits use the parity
# of age + height + weight rolled at birth.  The pref files will need a $SEX
# variable in ui-prefs.c computing the same thing, so the map and the
# portrait always agree.

# feat-floor is not cut from a sheet.  The importer draws it: one plain iron
# slab per square with bevelled joints, chosen on 2 November 2026 over the
# generator's bricks, which hid the figures.  The owner picked the bevelled
# slab, top right in floor-slab-options-2x.png.  floor.png is that slab at
# 32x32, and the importer must draw exactly it.  Counting x and y from 0 at
# the top left:
#
#   everything iron, then
#   column 31 and row 31 ink                    the joint
#   row 0 and column 0, from 0 to 30, stone     the lit edges
#   row 30 and column 30, from 1 to 29, plum    the shaded edges
#   (0,0) (30,0) (0,30) (30,30) ink             rounded corners
#   (1,0) (0,1) iron
#
# Every figure, item, trap and effect also gets a one-pixel ink outline
# (4-way, outside the shape, inside the tile).  The exception, ruled by the
# owner on 7 November 2026: a tile of which nine-tenths or more of the
# pixels are darker than the floor's iron (relative luminance, sRGB, below
# iron's 0.071) is outlined in stone instead, so its silhouette shows on the
# dark floor.  Measure the tile as the game will show it: after the colour
# swaps and, for a recolourable tile, after tinting it to the monster's
# colour, so a recolourable spider tinted near-black gets the stone outline
# too.  Of the fixed figures accepted by then, 13 qualify, from Draebor the
# Imp at 99% to the hero rogue at 90% (batch-25/darkest-1x.png, the 30
# darkest with ink above and stone below; batch-25/rim-1x.png).  Traps are drawn on magenta
# and laid on feat-floor, like the rubble, and outlined like the items: at
# actual size the outline is what makes a trap show (batch-12/rune-1x.png).
#
# Steps for particular tiles:
#   - feat-rubble and feat-pass-rubble are drawn on magenta: key it out and
#     lay what is left on feat-floor.
#   - Buildings drawn with magenta round them (the batch 6 services, the
#     batch 7 Figurine Store and both towers): key it out and lay what is
#     left on feat-grass.
#   - feat-chaostower is lifted a step after snapping, which turns its drawn
#     outline plum, so it then gets the ink outline as the figures do.
#   - Every shop front gets its number stamped on the gable: 3x5 digits in
#     bone on an ink box, top left at (14,6), the box one pixel larger all
#     round.  The numbers are terrain.txt's glyphs: General 1, Armoury 2,
#     Weaponsmith 3, Bookseller 4, Alchemist 5, Magic 6, Black Market 7,
#     Home 8, Statue Store 0, Figurine Store 0, and the Magetower 9.  The
#     owner approved it on 2 November 2026 (batch-02/town-fixes-2x.png,
#     bottom half): the signs alone can't be told apart at actual size.
#   - The five services, whose glyph is +, get a letter the same way:
#     Healer H, Inn I, Magesmith M, Recharger R, and the Chaos Tower C.  The
#     owner ruled for letters over a + on 3 November 2026, since a + would
#     tell the services from the shops but not from each other
#     (batch-07/street-3x.png shows the whole street marked).
#
#     The digits and letters, one row per line, 1 = bone:
#       1  010 110 010 010 111     6  111 100 111 101 111
#       2  111 001 111 100 111     7  111 001 010 010 010
#       3  111 001 111 001 111     8  111 101 111 101 111
#       4  101 101 111 001 001     9  111 101 111 001 111
#       5  111 100 111 001 111     0  111 101 101 101 111
#       H  101 101 111 101 101     R  110 101 110 101 101
#       I  111 010 010 010 111     C  111 100 100 100 111
#       M  101 111 111 101 101
